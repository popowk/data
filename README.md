# PhoneHub 授权管理后台

面向 PhoneHub 0.7.1 的独立 PHP + MySQL 管理面板。**不替换、也不修改现有** `/phonehub/api.php` 客户端授权接口。可直接连接 PhoneHub 原有数据库。

- 当前版本：**0.3.0**
- 环境：PHP 8.2+、MySQL 5.7.8+、PDO MySQL；AI 代理需要 PHP cURL、sodium，客户端核心更新需要 PHP ZipArchive、sodium。
- 无 Composer、无 Node.js、无 SSH/命令行安装步骤。

## 第一次安装

1. 下载仓库 ZIP，将内容解压到 PHP 网站目录（建议专用子目录，如 `/license/`）。
2. 确保 PHP 进程可写入站点目录的 `storage` 子目录和程序目录（仅更新时需要写权限）。
3. 打开 `https://你的域名/license/`，系统自动跳转 `install.php`。
4. 输入数据库主机、端口、数据库名、用户名、密码，以及**新的后台管理员账号和密码**。
5. 点击「连接数据库并完成安装」即可，自动创建缺少的表，**不会删除、清空或重置已有的 PhoneHub 用户、会话、平台包**。

**重要**：如需管理已有 PhoneHub 客户，必须使用客户端服务所连接的**同一数据库**。管理后台的管理员账号独立于 PhoneHub 客户账号；原有 owner 用户不会自动变成管理员。MySQL 用户需要建表及读写权限；生产部署建议最低授权。安装后 `storage/config.php` 为真实私有配置，**严禁提交到 GitHub**。

## 功能

- 控制台：用户、启用账号、未过期电脑会话、分组概览。
- 客户：创建时自动生成随机密码、编辑、启停、续期、单独重置密码；授权平台、电脑/手机名额与 AI 使用权限。
- 分组：创建分组、用户归组、空分组删除。
- 电脑会话：未过期会话查看、单个撤销、客户全部撤销。
- 手机数量：新增独立安卓设备绑定、解绑与心跳 API；原有客户端 0.7.1 暂未接入，需要未来 APP 配合。**接管旧 API 后，未绑定手机的客户不能下载操作包**。
- 平台操作包：管理端只读查看版本，客户端支持 package_list / package_check / package（强制已绑定安卓手机）。
- 审计：记录管理端的授权修改、分组和会话管理操作。
- 在线更新：管理端「系统更新」页面自动检查版本，确认后**经 `https://git.wksite.cn/popowk/data` 镜像下载代码 ZIP、备份并替换程序文件**。无需服务器手工执行命令。
- AI 接口：默认服务器中转 DeepSeek `deepseek-flash`，服务端密钥加密保存；客户 BYOK 需要主管理员全局开启且客户单独获权。
- 客户端上传/下载：日志上传、操作包下载和核心更新下载均要求有效 Bearer 会话、设备匹配、账号授权检查；日志限流，更新包验签清单和 SHA-256。
- 页面表单由 AJAX 提交；保存授权/分组后局部更新主要内容，不重新加载整个页面。

## 在线更新

当前源码 ZIP 使用以下国内代理 URL：

`https://git.wksite.cn/popowk/data/archive/refs/heads/main.zip`

该地址依赖代理网站确实支持 GitHub ZIP 下载而非只代理网页；**尚未在你的国内生产服务器上实测**。请先在浏览器或后台「检查更新」验证。如果代理重定向到其他域名，更新器将拒绝；需要调整国内镜像的 ZIP 代理规则。首次推出 v0.1.0 后，未来提交新版本必须同步递增仓库根目录 `version.json` 的 version 字段，否则不会显示更新。

更新器仅允许替换固定清单中的程序文件，禁止随 ZIP 内容覆盖任意路径，不覆盖 `storage/config.php`、现有数据库、签名私钥或客户端 API。更新器会锁定并备份已有文件；异常会尝试回滚，建议重要环境升级前另做网站与 MySQL 备份。

**安全须知**：管理后台自身的 GitHub 镜像自更新与客户软件核心更新是两套通道。客户核心 ZIP 发布使用 Ed25519 清单签名和 SHA-256；管理后台自身镜像更新仍依赖 HTTPS、固定镜像域名、ZIP 路径检查和人工确认，不要开启无人工确认的无人值守更新。

## Web 安全

- 生产站点**务必使用 HTTPS**。
- 对 `storage/` 禁止所有 HTTP 访问；Apache 可使用仓库随附 `storage/.htaccess`，若用宝塔/Nginx，请把仓库 `deploy/nginx-license-storage.conf` 中的规则加入 HTTPS `server {}` 块（按实际安装路径修改），防止备份、AI 主密钥、签名私钥及更新包被直接访问。
- 确保 PHP 源码由 PHP-FPM 执行，不得作为静态文本下载。
- 建议针对管理入口限制 IP 或再加 WAF，定期备份数据库；管理员密码至少 12 字节。
- 将前端目录与当前已有 `/phonehub/api.php` 分开；**不要覆盖已有客户端 API**。
- 不要向公网暴露 `/storage/`，不要把数据库配置、客户端签名私钥、真实用户数据传到公开 GitHub。

## 从已部署的 v0.1.0 升级

主管理员打开「系统更新」并执行更新。较早版本的更新器只认识旧文件清单，因此**第一次更新后可能显示新版本号，但仍缺少新功能模块**。更新页会自动检测缺失模块并显示「补齐缺失模块」，请再点击一次。无需上传新文件或执行 SQL。完成后可看到「AI 接口管理」等新菜单。

正式修改 APP 前，请勿在「客户端接口接管」页面强制接管生产旧 API，否则未绑定手机的旧 APP 将无法下载操作包。

## v0.3.0 扩展功能

- **主管理员不可被其他管理员操作**：第一个管理员在迁移时被标记为 owner；普通管理员可创建、停用、重置或删除（仅 owner 能管理其他管理员）。后台与客户端核心更新仅 owner 可操作。
- 新建客户自动生成高强度随机密码，网页弹窗仅显示一次；重置客户或普通管理员密码也只显示一次。
- 统一修改指定分组的电脑名额、安卓手机名额、授权期限、启停状态与平台权限；只覆盖勾选的字段。
- 手机注册、查询、解绑、心跳；操作包下载必须至少有一台有效绑定的安卓手机。
- 客户端核心代码版本发布：管理员上传 ZIP，服务端生成 SHA-256 与 Ed25519 签名，客户持有效令牌查询版本、分段下载、校验安装。
- 运行日志：单条/批量上传、服务端脱敏、按客户限流、查看与清理。
- 电脑名额自助查询、撤销旧会话、可选换电脑登录。
- 版本化自动迁移：升级后的首次后台访问自动应用缺少的表/字段，无需手工 SQL。
- AI 服务端中转：默认 DeepSeek `deepseek-flash`，服务器密钥使用 sodium secretbox 加密保存，后台不回显密钥。
- AI 客户端自带 Key：默认关闭；必须由主管理员开启全局开关，并在客户编辑页单独授权。客户端 Key 仅随 HTTPS 请求转发，不保存在服务端。
- AI 每客户每分钟/每日额度、最大输出 Token、请求超时和响应大小限制；调用日志只保存模型、Token 用量、状态与耗时，不保存 Prompt 或 Key。

完整客户端接入协议：[docs/客户端接入API-v0.3.md](docs/客户端接入API-v0.2.md)，包含 AI 代理与 BYOK 接入。

**强制手机绑定的上线提醒：** 升级后台本身不会自动覆盖生产原接口。完成客户端适配之后，主管理员在「客户端接口接管」页面备份并接管原 /phonehub/api.php。当前老版本 APP 不会自动注册手机，若现在启用强制检查，尚未绑定手机的客户会立即无法下载操作包；可先使用 /license/api/phonehub.php 测试。

**安全配置：** 发布核心 ZIP 要启用 PHP sodium、ZipArchive，AI 中转还需要 PHP cURL；上传较大 ZIP 时配置 upload_max_filesize≥50M、post_max_size≥55M。必须备份 `storage/ai-master.key` 与数据库（其中保存加密后的 DeepSeek Key），并确保宝塔/Nginx 禁止任何人通过 HTTP 访问 `/license/storage/`，否则主密钥、签名私钥、ZIP 及数据库配置可能泄露。

## 兼容性与注意事项

- `license_until`、`expires_at` 采用 UTC 存储，界面以北京时间显示；新增或更新账号不会把历史 `created_at` 自动假定为 UTC。
- 现有电脑 `device_limit` 本质为 8 小时未过期的安装会话名额，不是不可复制的硬件指纹绑定。
- 修改密码、停用账号或降低电脑额度时自动撤销该客户全部会话；正常修改备注、分组或延期不会重置密码。
- 需要 PDO MySQL + Argon2id；PHP 8.2+、MySQL 5.7.8+。
- 首次安装所使用的数据库中不得已有无法恢复的 PhoneHub 管理员；发现已存在管理员但缺少配置时会安全拒绝覆盖。
