# PhoneHub v0.5.2：统一设备管理与敏感标识说明

本文档仅描述服务端 API 和后台行为。**不修改 Windows APP，也不修改用户自定义 README.md。**

## 一、统一设备管理

主管理后台进入「设备管理」，不再分成「电脑会话」和「安卓手机」两个菜单。

- 「电脑设备」：客户账号、电脑 device_id（可复制完整 SHA-256）、有效会话数量、到期时间、踢下线、独立拉黑电脑 ID
- 「安卓手机」：账号、手机型号、备注、手机指纹、IMEI、手机号、绑定状态与最近使用时间；支持单独拉黑手机指纹、IMEI 或手机号
- 「禁止访问」：独立新增、查看、解除四类黑名单：\`computer_id\`、\`phone_id\`、\`imei_hash\`、\`phone_hash\`，带原因、审计记录和即时会话/绑定撤销

原有 \`?view=mobiles\`、\`?view=sessions\` 链接转向新 \`?view=devices\`。电脑只显示未过期的会话，不代表实时在线；旧客户端可继续按原协议登录。

### 管理员权限

一般管理员可以浏览设备与脱敏信息、执行已有的解绑/会话撤销操作。**完整 IMEI 和手机号只对主管理员提供单字段、主动点击后的查看**，每次读取写入审计记录（账号、时间、动作、设备记录号）。拉黑操作也仅主管理员可以执行；非主管理员看不到相关按钮，服务端仍需强制鉴权。展示层默认遮盖数字，客户端 API 不下发完整敏感标识。

## 二、客户端手机绑定接口增加的可选字段

\`POST /license/api/phonehub.php?action=mobile_bind\` 的原有必填字段和授权检查不变，可额外提交：

~~~json
{
  "device_id": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "phone_id": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "display_name": "客户的安卓手机",
  "phone_model": "Samsung Galaxy S24",
  "imei": "490154203237518",
  "phone_number": "+8613912345678"
}
~~~

\`phone_model\` 最长 120 字符；\`imei\` 允许 14～16 位数字；\`phone_number\` 支持国际 \`+国家码号码\` 格式，合法大陆手机号的 11 位形式会归一化为 \`+86\`。这些字段都是可选项。未收到就保留旧记录并显示「未获取」。**不要用占位文字、随机号码或其他设备号码冒充真实号码。**

正常 Android 10+ 三方应用不能依赖读取 IMEI；Android 的本机电话号码也常常缺失、被运营商/SIM 设置省略或受权限限制，即使 ADB 连接正常也不等于一定能拿到。建议由用户明确告知并确认后上报。手机号是**客户端声称的未核验字段**，不构成运营商验证或唯一硬件身份。

### 加密保存与兼容

迁移版本 8 **只增加字段，不删除旧手机绑定记录**：

- \`phone_model\`：手机型号
- \`imei_encrypted\`：原始 IMEI 的 sodium secretbox 密文（不会明文写数据库）
- \`phone_number_encrypted\`：原始手机号密文
- \`phone_number_hash\`：标准化手机号的 keyed HMAC-SHA256 摘要（用于拉黑与快速匹配）
- 旧的 \`imei_hash\` 保留，使用已存在的 \`storage/mobile-identity.key\`，不会重新生成/轮换原身份密钥

原文加密使用从 \`mobile-identity.key\` 派生的用途隔离子密钥。该文件**必须有加密异地备份**；丢失后既有原文无法解密，历史 HMAC 黑名单匹配也会失效。不能自动生成替换密钥。

历史只存过摘要的 IMEI 不可能恢复出原文；等待合法客户端重新上报或由主管理员核对后录入。普通设备列表只显示遮盖/保存状态，完整值需审计权限。

## 三、独立黑名单行为

| 禁止类型 | 匹配对象 | 立即处理 | 后续校验 |
|---|---|---|---|
| 电脑 ID | SHA-256 device_id | 撤销匹配电脑的所有有效会话 | 登录、Bearer 会话均拒绝 |
| 手机指纹 | phone_id | 停用匹配手机绑定 | 手机绑定、心跳、下载许可拒绝 |
| IMEI | HMAC(原始 IMEI) | 停用匹配的手机绑定 | 手机绑定、心跳拒绝 |
| 手机号 | HMAC(标准化手机号) | 停用匹配的手机绑定 | 手机绑定、心跳及手机额度计算拒绝 |

独立拉黑一个类型不会自动拉黑另外三个类型。新建黑名单、解除拉黑、查看完整身份都有管理员审计。已解绑或拉黑的手机不会自动重新启用。

**边界：** 设备指纹、IMEI、手机号本质上是客户端提交的属性，均可能缺失或被修改。普通 APP 无法由此保证不可伪造的设备认证；要实现更强的设备证明，需要受信任客户端、设备证明或硬件密钥，不能仅靠服务器黑名单。

## 四、Ed25519 签名密钥由后台生成

主管理员进入「系统更新 → Ed25519 签名密钥管理」。

1. 输入**本次使用的** GitHub Token（需对 \`popowk/data\` 仓库具有 Actions Secrets 写入和工作流触发权限），点击「生成密钥并自动配置签名」。
2. 网站在本次请求的内存中生成 Ed25519 密钥对，使用 GitHub 官方 Secrets 公钥进行 sealed-box 加密，发送至 \`PHONEHUB_SERVER_SIGNING_KEY_B64\`；**不将私钥或 GitHub Token 长期保存在网站或数据库中**。
3. 网站临时保存待启用的原始 32 字节公钥，自动触发 GitHub Actions 的版本签名工作流。
4. 等待签名发布及国内镜像同步，点击「验证镜像并启用签名」；只有镜像 ZIP 的版本、文件摘要和签名全部通过验证，才把待启用公钥原子移动到正式固定信任位置。
5. 固定公钥一旦启用，所有后续服务器更新都必须通过 Ed25519 验签；不支持通过后台重新生成新密钥来覆盖信任链。

后台初始化依赖 GitHub API 可访问性以及有效 Token。请求失败时不会把未签名来源自动设为信任。**生成私钥的 PHP 服务器是信任边界的一部分**；相比纯离线密钥方案，服务器运行时被完全攻陷时可能影响密钥生成和传输。建议主分支保护、限制管理员权限，并独立备份公钥指纹。新密钥与已有客户端核心更新签名密钥完全独立。

## v0.5.16 上报状态说明

统一设备管理会区分「客户端未上报」与「仅有历史摘要（需补报）」，保护旧的 HMAC 和密文记录，不尝试从摘要反推原号。
客户端可在用户知情且能合法读取时，通过 mobile_bind（同一 phone_id 的再次绑定）或 mobile_heartbeat（已绑定设备身份补充）传入 imei、phone_number、phone_model。两者都沿用原有 Bearer 鉴权、设备指纹、黑名单与身份一致性校验。
这不是服务端主动读取 USB/Android 的机制；只发 phone_id 的旧客户端会继续显示客户端未上报。client_heartbeat.batch 的 imei 保持仅核验。
