## 最新进展（v0.5.26 → v0.5.27）

- **P0 已修复**：`account_save` 服务端拒绝自定义客户密码，创建仍随机生成；修改只能走专用密码重置接口。设备管理从合并的电脑行撤销时，会按该客户和电脑指纹删除全部会话，而非只删单个 Token。
- **P1 自动换机审计**：v0.5.26 已支持电脑满额自动替换；v0.5.27 增加脱敏换机计数事件，15 分钟内自动换机达到 5 次仅在设备管理页面提示，不自动封禁。记录不包含旧设备指纹、IP 或 Token。
- **P1 并发验证**：增补独立 PHP 进程同时登录并叠加管理员修改电脑名额的事务回归测试，以客户行锁维持名额上限。
- **P1 性能测量**：扩充原有采样至 `license_status`、`capabilities`、`client_config` 和 `client_heartbeat`；日志仅输出接口动作、HTTP 状态与耗时/SQL 计数，运营可聚合计算 P50/P95。**没有真实生产样本时不声称 2198ms 已优化到某个值**。
- **P2 设备管理**：电脑、安卓手机、黑名单按类别服务端分页，每页 30 条；提供客户账号、设备标识/型号/备注或黑名单原因搜索，并显示真实总量。
- **官网主程序下载链接与官网首页**：用户已确认生产端的官网主程序下载配置已更新，独立官网首页也已完成，不再列入未开发项目。仓库内的首次安装默认 ZIP 仍是初始化值，并非生产部署的实时设置。
- **生产环境**：用户表示安全配置已完成，后续版本不继续重复此项；新版本部署验证仍由用户在实际服务器完成。

## 2026-11-20 · v0.5.28 新增

- **历史记录安全清理**：仅全局管理员可在「系统维护」按类别明确发起「预览 → 确认 → 每次至多 500 条」旧历史删除；普通管理员禁止。客户端日志至少保留 7 天、AI/自动换机至少 30 天、操作包下载至少 90 天、管理员审计至少 365 天（仅主账号可清理）。不会删除客户、授权、设备、会话、操作包文件、密钥或签名。默认不启用自动定时删除；如需定时任务必须另行明确授权和运维部署。
- **手机绑定客户搜索**：不再从前 1000 位客户下拉选择，先在设备管理通过用户名筛选任意客户，最多加载 25 个结果，防止大批客户下拉失效。
- **发布历史分页**：签名更新版本及加密操作包版本分别按 50 条分页并按关键词筛选；操作包汇总统计不再错误地依赖当页的 50 条历史记录。历史操作包密钥仍不返回到后台 HTML。
- **用户已完成的官网相关功能**：官网主程序下载地址和独立官网首页不重复开发，也不从服务器代码默认占位值推断实时生产配置。

## v0.5.29 性能监控

- 新增「接口性能监控」全局管理员页面，查看采样请求的 HTTP 错误率、P50/P95、数据库耗时、查询次数与 UTC 每日趋势（近 7 天最新至多 3000 条）。
- 数据库迁移 15 存储脱敏采样，不记录客户、设备、IP、Token 或正文。采样比例仍通过 PHP-FPM 环境变量手动设置，默认关闭；不能凭脱敏样本声称全站性能已提升。
- 采样历史可通过 v0.5.28 的受控分批清理功能删除，至少保留 7 天。

## v0.5.30 客户端版本与历史检索

- 新客户端可在 `update_check` / `update_manifest` / `update_list` / `update_download` 可选上报自身核心 `client_version`，服务器对比已签名发布包的 `min_client`，提供兼容提示并拒绝上报版本过低的下载。**旧客户端不传版本时不变，绝不默认开启全局强制登录阻断。**
- 「版本发布与操作包」新增旧操作包下载历史按账号/包 ID 检索和 50 条分页，仅显示必要元数据、不输出完整设备指纹；与核心签名 ZIP 下载历史属于不同系统。
- 管理员操作记录支持关键词检索，客户列表可直接跳转账号相关的历史目标文本。旧操作只保存摘要或 ID，不虚构不存在的字段差异。完整客户授权变更快照仍属于后续独立功能。

## v0.5.31 · 客户初始密码、抖音操作包分类与旧版 core 清理

- 新建客户时可选择 **自定义初始密码**（长度 12–128 字节），也可以留空由服务器自动生成安全随机密码；创建成功仍只返回一次明文给创建者。**编辑现有客户仍不允许顺带更改密码**，必须使用独立重置功能，避免越权改密。
- 旧协议操作包 `douyin` 和 `douyin-notification` 属于同一 **抖音** 业务分类，共享客户的 `douyin` 授权，但仍保留各自独立的包 ID、版本、上下架与下载统计。服务端客户端接口 `package`、`package_check`、`package_list`、批量心跳均能正确返回两个包；其他任意 `douyin-*` ID 不会因为前缀相似而被授予权限。
- 已停用且比同渠道已启用 core 版本更旧的 `core` **客户端签名 ZIP** 可由主账号在「版本发布与操作包」永久删除。后台需再次确认，服务器校验权限、core 类型、停用状态、同渠道较新启用版本、文件路径与唯一引用，并保留审计。此次删除不会清理服务器自身的版本安装/回滚文件、Ed25519 密钥、操作包或用户数据。**不自动批量删除历史版本**。
- 官网首页与官网主程序下载配置此前已由用户完成；本版不更改生产现有网址或下载配置。

## v0.5.32 · 客户授权变更明细

- 新增 MySQL 5.7 兼容数据库迁移 **16**：`phonehub_account_change_events`。记录创建客户、编辑客户授权、每位客户的批量授权变化、密码重置的管理员和 UTC 时间。
- 采用事务内一致的 **字段白名单快照差异**，记录账号、套餐代码、分组 ID、电脑/手机额度、有效期、平台权限、账号状态、AI 开关、自带 Key 许可和 AI 日额度的修改前/后值。备注只记录「已修改」标记，绝不保存原文；密码哈希、明文密码、Token、API Key 都不进入新表。
- 只有实际修改才产生 `update` / `group_bulk` 事件；`create` 记录初始可见授权；`password_reset` 仅记录操作本身。写入失败会和授权更新一起回滚；批量更新逐客户留痕。
- 客户列表的「变更明细」按稳定客户 ID 打开只读时间线，每页 25 条并可检索更早的事件，只有主账号/全局管理员有权限。原有「操作记录」概览仍保留。
- 不根据旧版的概要审计重建不存在的字段差异；升级前的历史不显示为完整授权变更。记录默认长期保留，本版不增加自动历史清理规则。

## v0.5.33 · 分组批量授权精确变更

- **不修改单客户多管理员并发编辑功能**（用户已要求忽略）。
- 分组批量预览按客户计算字段前后差异、实际改变人数和预计下线会话，提交时验证目标值与全部相关原授权状态，过期预览拒绝操作。
- 仅对确实需要下线的客户撤销会话，增加额度/权限/期限与无变化保存不再误踢；数据库已有事务与细粒度授权变更审计保持不变。
- 下一步按实际需求补授权到期/用量提示、历史导出、版本列表健壮性；对超大分组的批处理需明确中途失败恢复机制后再单独实施。

## 一、项目定位与已有能力

- 部署：独立 PHP 管理后台，PHP 8.2+、MySQL 5.7 兼容；网页初始化、后续在线更新；国内镜像 `https://git.wksite.cn/popowk/data`。
- 现有基础：主管理员与管理员、客户与分组、电脑会话与安卓设备绑定/黑名单、授权到期和限额、平台操作包、AI 中转及 BYOK 授权、MCP/Skill 权限、审计和客户端 API。
- 更新安全：服务端自更新使用预置 Ed25519 固定信任公钥验证签名清单，客户端核心更新使用另一套独立密钥；更新器仅替换白名单程序文件并尽力回滚，保留数据库、`storage/` 及用户现有 `README.md`。
- v0.5.4：可复制的脱敏故障诊断报告、创建客户时选择开户额度模板。
- **v0.5.5 已实现**：
  1. 套餐管理：新增、编辑、排序、启停；模板仅包含电脑/安卓手机名额；停用套餐不可用于新开户，已开户用户的额度与开户标签不被模板变动追改。
  2. 备份接收密钥：主管理员一次性生成 Curve25519 密钥对，服务器只持久化公钥，私钥仅通过受保护的下载响应交付；与更新签名密钥隔离。
  3. 故障诊断增强：成功更新记录、备份接收公钥状态、CLI 加密备份工具存在性等检查；输出继续脱敏。
- 仓库自动化包含 PHP 语法、JavaScript 语法、MySQL 5.7、API、加密备份、签名验证与升级回滚等检查；**CI 通过不等于生产环境已经验收**。

## 二、已确定的产品边界

1. **优先级明确**：继续围绕「备份密钥管理、故障诊断增强、套餐管理」完善安全性、可用性与回归测试。
2. **本阶段不做**：自动备份任务状态监控、异地备份/同步状态检查；不得在诊断页伪装成已检查或已通过。
3. 套餐当前是**开户额度模板**，不是商品或订阅：暂不引入价格、订单、支付、自动续费、套餐自动扣费。
4. 套餐变更不能自动赋予 AI、MCP、Skill 或额外平台权限；这些继续由既有授权和全局开关独立控制。
5. **明确排除多软件产品授权与跨产品授权中心**：保持 PhoneHub 单一授权体系，不开发多产品目录、产品级独立授权、跨产品订单；今后的设计与数据库迁移不得以多产品作为前置条件。
6. Windows 客户端 APP 不由本仓库开发；仅保留服务端 API 兼容、协议文档与联调测试。
7. 不覆盖生产数据库、`storage/`、签名信任公钥、加密私钥或已有客户授权；不擅自修改用户的 `README.md` 结构。
8. 备份工具仍使用既有 CLI 与外部计划任务；私钥须离线保管，恢复须在隔离环境中演练，不直接恢复覆盖线上库。

### P3 · 长期运维与性能（按使用规模决定）

- 审计检索、保留期限与安全导出；不输出敏感密钥/明文个人信息。
- 大客户量下的后台分页、索引、API 限流及数据库查询性能基准。
- 版本目录与原子切换方案调研；若要实现真正零中断发布，必须先改变部署架构并制定回滚边界。
- 备份自动执行、异地同步、灾备编排**不在当前批准范围内**；未来仅在明确新增需求后单独评审。

## 五、功能变更与发布规则

1. 小版本先完成代码、兼容性、自动化测试、文档四项，再发布；不要因为文档中出现版本号就认定已部署。
2. 数据库迁移只能使用可重入、兼容 MySQL 5.7 的增量结构更新；老客户的授权和来源标签必须保留。
3. 已启用固定自更新公钥的站点坚持「签名清单 + 文件 SHA-256 + 版本校验」；不可为便捷退回未验签更新。
4. 既有更新器只安装 `UPDATE_FILES` 白名单中的文件。**本规划文档只作为 GitHub `docs/` 资料维护，不会自动同步到已安装站点**；若未来需要网站内展示，须另行安排签名白名单变更与版本升级。
5. 生产验收应记录升级前版本、升级后版本、数据库迁移版本、签名状态、回滚结果及需人工确认的警告，不上传私钥或生产数据库。
