# PhoneHub 后续功能规划与开发路线图

> 更新日期：2026-11-17  
> 规划基线：v0.5.5（`popowk/data` 的 `main` 分支）  
> 范围：**服务端授权管理后台**。这是一份可执行的规划，不表示未完成事项已经上线；优先级和版本号均为建议，实际以验收结果为准。

## 一、项目定位与已有能力

- 部署：独立 PHP 管理后台，PHP 8.2+、MySQL 5.7 兼容；网页初始化、后续在线更新；国内镜像 `https://git.wksite.cn/popowk/data`。
- 现有基础：主管理员与管理员、客户与分组、电脑会话与安卓设备绑定/黑名单、授权到期和限额、平台操作包、AI 中转及 BYOK 授权、MCP/Skill 权限、审计和客户端 API。
- 更新安全：服务端自更新使用预置 Ed25519 固定信任公钥验证签名清单，客户端核心更新使用另一套独立密钥；更新器仅替换白名单程序文件并尽力回滚，保留数据库、`storage/` 及用户现有 `README.md`。
- v0.5.4：可复制的脱敏故障诊断报告、创建客户时选择开户额度模板。
- **v0.5.5 已实现**：
  1. 套餐管理：新增、编辑、排序、启停；模板仅包含电脑/安卓手机名额；停用套餐不可用于新开户，已开户用户的额度与开户标签不被模板变动追改。
  2. 备份接收密钥：主管理员一次性生成 Curve25519 密钥对，服务器只持久化公钥，私钥仅通过受保护的下载响应交付；与更新签名密钥隔离。
  3. 故障诊断增强：成功更新记录、备份接收公钥状态、CLI 加密备份工具存在性等检查；输出继续脱敏。
- 仓库自动化包含 PHP 语法、JavaScript 语法、MySQL 5.7、API、加密备份、签名验证与升级回滚等检查；**CI 通过不等于生产环境已经验收**。

## 二、已确定的产品边界

1. **优先级明确**：继续围绕「备份密钥管理、故障诊断增强、套餐管理」完善安全性、可用性与回归测试。
2. **本阶段不做**：自动备份任务状态监控、异地备份/同步状态检查；不得在诊断页伪装成已检查或已通过。
3. 套餐当前是**开户额度模板**，不是商品或订阅：暂不引入价格、订单、支付、自动续费、套餐自动扣费。
4. 套餐变更不能自动赋予 AI、MCP、Skill 或额外平台权限；这些继续由既有授权和全局开关独立控制。
5. **明确排除多软件产品授权与跨产品授权中心**：保持 PhoneHub 单一授权体系，不开发多产品目录、产品级独立授权、跨产品订单；今后的设计与数据库迁移不得以多产品作为前置条件。
6. Windows 客户端 APP 不由本仓库开发；仅保留服务端 API 兼容、协议文档与联调测试。
7. 不覆盖生产数据库、`storage/`、签名信任公钥、加密私钥或已有客户授权；不擅自修改用户的 `README.md` 结构。
8. 备份工具仍使用既有 CLI 与外部计划任务；私钥须离线保管，恢复须在隔离环境中演练，不直接恢复覆盖线上库。

## 三、分阶段任务

### P0 · 稳定性与上线验收（下一步，优先实施）

| 编号 | 任务 | 完成标准 | 状态 |
|---|---|---|---|
| P0-01 | 套餐回归测试：默认模板、增改、启停、排序、禁用后开户拒绝、模板调整不追改老客户、重复迁移 | MySQL 5.7 自动测试覆盖有效/无效路径；没有隐性授权扩张 | 已补基础生命周期回归；补充管理端非法输入测试待办 |
| P0-02 | 备份密钥安全验收：主管理员权限、CSRF、只允许首次创建、并发拒绝覆盖、下载禁止缓存、原始密钥长度与离线解密 | 不持久化私钥；旧更新签名密钥不改变；异常时安全失败 | 已有基础自动测试，待生产验收 |
| P0-03 | 故障报告脱敏回归：PHP/MySQL、迁移、签名、工具检查和更新记录；敏感字段不可进入报告 | 可一键复制；不含密码、Token、私钥、手机号、IMEI、客户账号与原始路径 | 已有基础自动测试，待生产验收 |
| P0-04 | 从 v0.5.4 到 v0.5.5 的签名在线升级与失败恢复演练 | 固定公钥验签成功；故意篡改包遭拒绝；保留客户与密钥；程序回滚行为可验证 | 自动化已有覆盖，待实机演练 |
| P0-05 | 生产部署检查及实际加密备份/离线恢复演练 | PHP 8.2、MySQL 5.7、Nginx 对 `storage/` 的访问限制、备份文件及恢复结果人工确认 | 待执行 |

**实施顺序**：先补齐 P0-01 的自动化回归，再跑全部 CI；随后按 [运维备份与升级](运维备份与升级.md) 在隔离或预发布环境验收 P0-02～P0-05。生产验收不应由开发环境结果代替。

### P1 · 管理体验与授权可维护性（P0 验收后；第一批已启动）

| 编号 | 方向 | 首期范围与验收口径 |
|---|---|---|
| P1-01 | 客户与授权检索 | **已实现 v0.5.6**：按账号、分组、状态、到期时间和开户套餐筛选；每页 30 条服务端分页 |
| P1-02 | 套餐使用情况 | **已实现 v0.5.6**：显示模板开户客户数、当前客户累计实际额度与自定义/历史授权统计 |
| P1-03 | 授权变更预览/审计 | **已实现 v0.5.7 的分组批量预检**：服务器返回成员数、字段和会话撤销提示；成员变化则拒绝旧快照；保留事务审计。更细粒度差异预览后续再做 |
| P1-04 | 最小权限管理 | **已实现 v0.5.8 首期**：新增只读管理员 viewer、owner/admin/viewer 的服务端页面和操作白名单、403 越权拒绝及 HTTP 回归；代理商/租户权限仍须单独实现 |
| P1-05 | 诊断用户体验 | **已实现 v0.5.6**：按「错误 / 需要确认 / 正常」分类和排查建议，继续输出脱敏报告 |

P1 的功能只改善现有授权业务，不隐含套餐计费或购买功能。

### P2 · 单产品授权体系扩展（方案评审后再开发）

| 编号 | 方向 | 必要的先决决策 |
|---|---|---|
| P2-01 | 代理商数据隔离 | 明确租户模型、所属客户关系、跨租户查询边界、管理员角色与数据迁移方式；先做越权测试 |
| P2-02 | 授权策略模板化 | 将「电脑、手机名额」与「可选产品/功能授权」分层建模；不把套餐默认扩大为收费订单 |
| P2-03 | 客户端协议兼容与发布管理 | 服务端增加协议版本与废弃策略，和独立开发的 Windows APP 联调验签/换机/回滚 |
| P2-04 | 密钥轮换与恢复机制 | 评审信任公钥迁移、重签流程、旧包处理与防回退；不得静默更换现有固定公钥 |

这些属于架构扩展，需兼容性设计及单独验收，不直接并入 P0 修复版本。

### P3 · 长期运维与性能（按使用规模决定）

- 审计检索、保留期限与安全导出；不输出敏感密钥/明文个人信息。
- 大客户量下的后台分页、索引、API 限流及数据库查询性能基准。
- 版本目录与原子切换方案调研；若要实现真正零中断发布，必须先改变部署架构并制定回滚边界。
- 备份自动执行、异地同步、灾备编排**不在当前批准范围内**；未来仅在明确新增需求后单独评审。

## 四、下一轮开发验收清单

- [ ] 套餐模板增改、启停与非法额度输入均有自动回归；停用模板不能用于新开户。
- [ ] 用测试客户验证：更改套餐模板后，旧客户额度、开户标签与 AI/MCP 权限保持原值。
- [ ] 检查管理员越权、CSRF、并发密钥生成、私钥 HTTP 下载响应；敏感信息不落审计和日志。
- [ ] 从带固定 Ed25519 公钥的 v0.5.4 升级，验签和失败回滚均能正常工作。
- [ ] 运行全部 GitHub Actions 检查，记录提交 SHA 与失败原因。
- [ ] 在**非生产**环境验证备份 `.phbk` 可解密、校验、隔离恢复，严禁拿线上数据做破坏性试验。
- [ ] 运维人员确认生产诊断中的警告及 Nginx `storage/` 屏蔽，不将「待确认」标记为通过。

## 五、功能变更与发布规则

1. 小版本先完成代码、兼容性、自动化测试、文档四项，再发布；不要因为文档中出现版本号就认定已部署。
2. 数据库迁移只能使用可重入、兼容 MySQL 5.7 的增量结构更新；老客户的授权和来源标签必须保留。
3. 已启用固定自更新公钥的站点坚持「签名清单 + 文件 SHA-256 + 版本校验」；不可为便捷退回未验签更新。
4. 既有更新器只安装 `UPDATE_FILES` 白名单中的文件。**本规划文档只作为 GitHub `docs/` 资料维护，不会自动同步到已安装站点**；若未来需要网站内展示，须另行安排签名白名单变更与版本升级。
5. 生产验收应记录升级前版本、升级后版本、数据库迁移版本、签名状态、回滚结果及需人工确认的警告，不上传私钥或生产数据库。
